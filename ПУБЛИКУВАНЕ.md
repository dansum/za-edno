# Публикуване на „Заедност" (Фаза 6)

Всичко нужно е подготвено в хранилището. Остават стъпките, които изискват
вашия акаунт в GitHub — тях трябва да направите вие.

## Какво вече е готово

| Файл | Какво прави |
|---|---|
| [`app/vite.config.ts`](app/vite.config.ts) | чете `BASE_PATH`, за да работят пътищата в подпапка на GitHub Pages |
| [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) | при вливане в `main`: тестове → проверка на типовете → изграждане → публикуване |
| [`app/.env.example`](app/.env.example) | образец за ключа при работа на вашия компютър |

Работният процес **спира публикуването, ако тестовете или типовете паднат** —
счупена версия не стига до потребителите.

## Стъпка 1 — хранилище в GitHub

От папката `mindmap-collab`:

```bash
git init -b main
git add .
git commit -m "Заедност — съвместни мисловни карти"
```

После създайте хранилище в GitHub (през сайта или с `gh repo create`) и:

```bash
git remote add origin https://github.com/<потребител>/<хранилище>.git
git push -u origin main
```

**Проверете преди push:** файлът `app/.env.local` с ключа НЕ трябва да влиза в
хранилището. Той е покрит от правилото `*.local` в `app/.gitignore`. Проверка:

```bash
git status --short | grep env
```

Ако този ред покаже `.env.local`, спрете и не публикувайте.

## Стъпка 2 — ключът като secret

В GitHub: **Settings → Secrets and variables → Actions → New repository secret**

- Име: `VITE_LIVEBLOCKS_PUBLIC_KEY`
- Стойност: публичният ключ от Liveblocks (`pk_…`)

Без този secret приложението ще се публикува, но ще работи само локално в браузъра,
без съвместна работа. Работният процес извежда предупреждение в такъв случай.

## Стъпка 3 — включване на Pages

В GitHub: **Settings → Pages → Build and deployment → Source: GitHub Actions**

След това всяко вливане в `main` публикува автоматично. Адресът е
`https://<потребител>.github.io/<хранилище>/`.

## Стъпка 4 — проверка след публикуване

1. Отворете адреса и вижте, че точката горе вдясно е зелена („Свързан").
2. Отворете същия адрес **на друго устройство** и проверете, че промяна в единия
   се появява в другия.
3. Проверете, че линк с `?room=…` се отваря директно.

## Собствен домейн (по избор)

При собствен домейн подпапката отпада. В `deploy.yml` заменете
`BASE_PATH: /${{ github.event.repository.name }}/` с `BASE_PATH: /` и добавете
файл `app/public/CNAME` със самия домейн.

## Какво да очаквате от безплатния план

Приложението показва знак **„Powered by Liveblocks"** долу вдясно — това е
условие на безплатния план и се маха само с платен план. Струва си да го знаете,
преди да пратите адреса на външни хора.
